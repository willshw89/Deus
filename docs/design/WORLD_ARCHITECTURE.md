# WORLD ARCHITECTURE: the DF-style world state and the plugins that share it

Written 2026-09-18 for engine steps 1–5 (DF_MECHANICS §14) as one build. This is the **contract** between the plugins listed in §5. Anyone writing one of them builds against this document, not against what another plugin happens to do today. Where a plugin's system doc (`docs/systems/UF_<Name>.md`) and this file disagree, this file wins until it's revised here.

User decisions this build implements (all in `docs/VISION.md`): V4 no fixed start except the pair, V13 look cursor, V16 emergence, V17/V23 autonomous colonists with an inner life, V19 edge arrivals (later), V21 everything shows physically, V24 populated world, V25 everything interactive, V27 all DF biomes, V28 DF mechanics as the model, and the 2026-09-18 additions: **one surface layer only (the underground layer is removed)**, **4-way movement** (DF-style), **DF map generation with DF's standard settings and no generation options in the game**, **600 years of history**, **colored squares under units by stance**, **pause on Space**, **every colonist job is a physical interaction**, **dense resources near the start**, **everything clickable with interaction options**, **assets designed with their interaction states in mind**, and **what the user wants to see first: a world full of natural resources, and the pair hunting, making tools and clothes, and cooking on their own**.

## 1. Principles (apply to every plugin)
1. **RMMZ plugins only**, aliases only (`const _x = Klass.prototype.m; Klass.prototype.m = function() {...}`). Never edit `rmmz_*.js`. Say in the plugin header which core methods are *replaced* (not aliased), if any.
2. **All simulation state lives in `UF.World.state`** (saved by UF_World as `contents.ufWorld`) or in `unit.data` of a world unit. Nothing that must survive a save lives in a plugin-local variable or in a window. Caches are fine if they rebuild from state.
3. **Generation is deterministic**: same seed, same world. Use `hash32`/`valueNoise` over world coordinates or `mulberry32(hash32(seed, salt, ...))`. **Never `Math.random()` in anything that shapes the world.** Runtime AI uses seeded randomness too: `hash32(seed, unitId, UF.World._frame)`.
4. **Content comes from `game/data/UF_WorldCatalog.json`** (schema §2.9). Code never hard-codes a species, plant, item, recipe or building. Placeholders are fine: many kinds share one image with a `tint` (user: "generate a large variety using duplicate placeholders").
5. **DF architecture, U7 look.** Cells hold an object; items lie on cells; units take jobs; jobs walk, work, then change the world. The screen shows exactly the state (V21).
6. **4-way movement** everywhere (UF_Movement8D `FourWay`, UF_World `stepToward`). Adjacent = the 4 orthogonal neighbors. Facings stay 4.
7. **Time**: 1 game hour = 1 real minute at ×1; `UF.Time.after/every(frames)` for timers (60 frames = 1 game minute); `$ufTime.hour` for the clock; `UF.Events.on("time:hour")`. Pause (§5.11) stops `Game_Map.update`, so anything driven from it pauses for free. **The beat (VISION V46, added 2026-09-18 evening, wired in at integration):** `UF.Beat` in UF_TimeSpeed: `BeatFrames` parameter (60 = 1 beat per second at ×1), `UF.Beat.count`, `UF.Beat.every(n, fn)`, event `beat(count)` on `UF.Events`; the speed multiplier plays more map updates per frame, so beats per second scale with it. Rules once wired: a unit starts at most one step per beat (`UF_World`: on-screen steps begin on a beat, off-screen units move one cell per beat instead of per `UnitStepFrames`); `UF_Jobs` adds `workRate × toolMultiplier` **per beat** and the catalog's `work` values are in beats (rescaled: chop 12, gather 3, pick 2, quarry 10, mine 15, build 4–8, craft 6–12, hunt 4–20); colonist needs tick per beat (= per game minute, unchanged). **Every living unit takes a turn every beat (VISION V48):** `UF.Beat` calls `UF.AI.turn(unit)` for every unit on every beat; the unit's driver (`data.ai`: colonist → UF_Colonists, wander → UF_Wildlife, others → stand) either continues its current decision (the next step toward its goal, the next stroke of its job) or makes a new one, and writes it to `unit.data.intent = { verb, text, target?, since: beat }` ("standing", "walking to the river", "chopping an oak", "fleeing a wolf", "grazing"). Wildlife's wander/flee rolls happen inside its turn (wander with a per-beat chance so the average stays ~35% per 3 beats; flee every beat while a hunter is near). UF_Look shows `intent.text`; the colonist card shows it as the job line. Nothing reads `Graphics.frameCount` for simulation.
8. **Performance budgets** (VISION V50; measured, not guessed): building the 256×256 map ≤ 1500 ms on this machine; per-frame work of any plugin ≤ 1 ms average at zoom ⅓ on the start area; all AI and simulation per beat ≤ 4 ms for ~400 units (one beat = 1 s at ×1, so ×8 still leaves headroom); tilemap children in view (objects + items + markers + characters) ≤ 1500 at the farthest zoom; 60 fps at ×1 and ≥ 30 fps at ×8 measured by the `perf` suite and recorded in STATUS per build; save contents ≤ 3 MB; no `Bitmap` created per frame, no full-map scans per frame (index by cell, cache built areas, invalidate on change). Draw only what's in view; pool sprites. Every plugin's suite includes a `perf` check for its own per-frame or per-beat cost.
9. **Tests that can fail** (`UF.Test.suite`), one suite per plugin, registered at `Scene_Boot.start` only when `UF.Test.active`. Every check names what it measured. Screenshots are opened and described in the report.
10. **Docs**: every plugin has `docs/systems/UF_<Name>.md` (§8). Absolute dates only.
11. **Asset marking**: every image or tile a plugin uses is either a catalog entry (found by `tools/generate_asset_inventory.js`) or listed in the plugin's system doc under "Assets used", so `docs/ASSET_INVENTORY.md` can say what still needs art. Code-drawn placeholders are named `UF_Gen*` and count as "generated".
12. **No DF or U7 words** in anything the player can read (names, events, labels, thoughts): AGENTS.md → Reference vs. shipped content.

## 2. Data model

### 2.1 Cell (per area; 256×256; one surface layer)
| Data | Where | Meaning |
|---|---|---|
| tile layers 0–3 | `$dataMap.data` (UF_World `data`, layer index `(z*h+y)*w+x`) | ground autotile (layer 0, A2 kinds from UF_Tiles) or water (layer 0, A1 kinds) |
| region (layer 5) | same | 250 = impassable rock (peaks) |
| **object** | `$dataMap.ufObjects` (Uint16Array, one per cell; `UF.World.getObject/setObject`; generators: `ctx.setObject`) | type number = index in `catalog.objects` + 1; 0 = nothing. Persisted per area in `state.objectDiffs[areaKey][cellIndex]` |
| items | `state.items` (§2.3) | list, located by area + cell |
| fluid level | later (step 6) | |

Areas are `{ x, y }` (no `z`; `areaMapId(ax, ay)`, `areaOfMapId(mapId) → {x, y}`). `UF.World.peekArea(ax, ay)` returns a cached build of an off-screen area for reading tiles/objects (AI, jobs, spawning). `UF.World.getTile/getObject` use it. Don't read its `events`.

### 2.2 Objects (UF_Objects)
Catalog `objects[]` entry (all fields optional except id/name and one of image/tile/gen):
```
id, name,
image: "!$TimberOak"      // character sheet in img/characters (3 columns x 4 rows). Frame = sidecar animations.stand[0], else column 1 row 0.
tile:  { sheet: "Outside_B", id: 157 }   // a 48x48 tile from a B/C tileset image (id 0-255 = B, 256-511 = C)
gen:   "stockpile"        // drawn in code (UF_Objects.generated[name] returns a Bitmap)
tint:  "#c8ffc8"          // PIXI tint (multiplies colors) so kinds can share an image
passable: false (default) // true = units walk through it
under: false (default)    // true = drawn under units (flat things: grass, stones, beds, stockpiles)
onWater: false            // generator: only on water cells (lily pads)
tags: ["tree","wood"]     // free strings; used: tree, bush, plant, stone, ore, gem, food, fiber, straw, remains, ruin, building, wall, bed, stockpile, fire, workplace, cursed
actions: { chop|gather|pick|quarry|mine: { work: frames, yields: {itemId: count}, becomes: "otherId" | null } }
regrow: { to: "id", hours: n }        // becomes `to` after n game hours (UF_Objects keeps state.regrow)
build: { items: {itemId: count}, work: n }   // a building: needs these items on its cell before it can be built (UF_Jobs "build")
ruin: "id"                // what it turns into when a site is sacked (UF_History) or later burns/collapses
clump, clumpScale, avoidWater  // generator placement (§3.6)
```
`UF.Objects.types()` is the catalog list with `typeId` (index + 1) added. **Nothing may use `Game_Event`s for world objects**; the old event-per-tree placement is gone.

### 2.3 Items (UF_Items)
`state.items = { nextId, byId: { [id]: item } }`, `item = { id, type, count, area: {x,y}|null, x, y, holder: unitId|null }`. On the ground: `area` set, `holder` null. Carried: `holder` set, `area` null. Stacks merge on a cell up to `catalog.items.types[].stack`. Item type fields: `id, name, image, tint, tags, stack, food: {hunger, thirst}, tool: {jobType: multiplier}, wear: {tier}`.

### 2.4 Units (UF_World; kinds by `unit.data.kind`)
`unit = { id, name, image: {characterName, characterIndex}, area: {x,y}, x, y, dir, goal, data }`. Common `data`:
```
kind: "colonist" | "creature" | "person" | "test"
faction: "player" | factionId | null     // wildlife: null
species: string                           // catalog species id (wildlife or people)
tags: [...]                               // wildlife: [species.kind] (grazer/predator/monster/flier/vermin)
tint: "#rrggbb" | undefined               // applied to the sprite by UF_Wildlife's Sprite_Character alias (any unit)
through: true                             // fliers: their events get through = true
ai: "wander" | "colonist" | null
home: { x, y }, wander: radius            // wander AI
jobId: number | null                      // UF_Jobs
inventory: [itemId]                       // UF_Items
equipment: { tool: itemId|null, clothes: itemId|null }
workRate: 1                               // job progress per tick (tools multiply it per job type)
sight: 8                                  // fog (player faction only)
```
Colonists add (§5.6): `gender, tier, tiers, needs {hunger, thirst, sleep, social, nature}, facets {name: 0-100}, skills {name: 0-20}, thoughts [{text, strength, hour}], moodScore, mood, jobsDone {type: n}`.

### 2.5 Jobs (UF_Jobs)
`state.jobs = { nextId, list: [job] }`, `job = { id, type, target: { area: {x,y}, x, y }, params: {}, owner: unitId|null (null = open, anyone may take it), assigned: unitId|null, progress, state: "open"|"travel"|"work"|"done"|"failed", reason, created }`. Job types are registered with `UF.Jobs.define(type, handler)`; the built-in ones are in §5.5. A job is the only way a unit changes the world. Open jobs with no owner are **designations** (what the player asks for by right-clicking, §5.10); colonists take them.

### 2.6 Colony (UF_Colonists)
**Revised 2026-09-18 (user): the player does not start with a naked pair. The player is given one of the generated factions, established during the world's history: its home site at the habitable centre of the map, and the people at that site are the colonists.** `state.factions.playerId` names that faction (§2.7); `state.colony = { factionId, plan: [{ id, ...step, done: bool | [cellIndex...] }], site: {x,y} (the home site's centre cell), siteId, stockpiles: [{x,y,stores:[tags]}], log: [] }`. `catalog.start.pair` is no longer used (kept in the file for reference only).

### 2.7 History (UF_History)
`state.history = { years, events: [{ year, type, text, factions: [id], site: id|null }], sites: [site], rulers: { [factionId]: [{ name, title, from, to }] } }`, `site = { id, faction, kind, area: {x,y}, x, y, founded, pop, ruined: year|null, name }`. `UF.History.sitesIn(ax, ay)` returns the sites of that area with `pieces: [{dx, dy, object: objectId}]`; the generator stamps them (§3.7).

**The player's faction (revised 2026-09-18):** `UF_Factions.generate` no longer makes a synthetic "player" faction; every faction is a generated one, and `generate` picks the player's (seeded; a species with `playable !== false` in the catalog, else any) as `state.factions.playerId` with `isPlayer: true`. History places that faction's **first site at the map centre** (the habitable start; cell (128,128) ± 6, on walkable land), and **protects that site from being sacked or abandoned** during the simulation (its other sites can fall). History also sets `state.viewStart = { x, y }` to that site's centre; `UF_World` starts the view there. `UF.Factions.player()` returns the faction with `playerId`; `UF.Factions.relation("player", id)` and `tierBetween("player", id)` treat `"player"` as an alias of `playerId`, so UF_Stance and older callers keep working.

### 2.8 Fog, factions, time: unchanged (`state.fog` keyed `area:x,y`, `state.factions`, `$ufTime`). Fog (user decisions 2026-09-18): **off during development** (`UF_Fog` parameter `Enabled` = false: the whole map is visible, `UF.Fog.isExplored` is always true, `reveal` is a no-op, no fog sprite); when it's turned on later, a cell once seen by the colony stays fully clear (`ExploredDim` 0) and unexplored cells are black. ## 3. World generation (UF_WorldGen + UF_Tiles): DF's map with DF's standard settings

Everything below is a pure function of the seed and world coordinates (`gx = ax*256 + x`, `gy = ay*256 + y`), so areas match at their edges and any cell can be classified without building its area. **World size: one 256×256 area** (user decision 2026-09-18; `UF_World` AreasX/AreasY = 1, start area (0,0), start cell (128,128)). The code keeps working for a grid of areas, but nothing may assume neighbors exist (`UF.World.inWorld` says). Field scales in the catalog are tuned so a single area holds several biomes.

### 3.1 Fields (all 0–1)
`fields(gx, gy)` returns `{ e, r, t, d, v, sav, al, sal }` using `valueNoise(seed, salt, gx, gy, scale)` at `climate.scale.*` plus a `detail`-scale octave at 25% weight:
- **e elevation** = noise × continent mask. Mask = `smoothstep(0, 1, min(distance to the nearest world edge in cells) / (worldWidth × climate.continentRim))`, so the world's rim is ocean or coast (a thin rim on a one-area world: `continentRim` 0.06 = about 15 cells).
- **t temperature** = clamp(0.15 + 0.7 × (1 − gy / worldHeight) + (noise − 0.5) × 0.4 − max(0, e − 0.5) × 0.6): north is cold, mountains are cold.
- **r rainfall**, **d drainage**, **v volcanism**, **sav savagery**, **al alignment**: noise.
- **sal salinity** = `clamp(1 − (e − seaLevel) / 0.08)` (near sea level = salty; brackish half-way).
- **Start blend**: at distance `dist` from the start cell, `e, r, t, d, v, sav, al` are blended toward `climate.startClimate` with weight `smoothstep(startHabitableRadius[1], startHabitableRadius[0], dist)` (1 at the start, 0 beyond 110 cells). The start is always a temperate, habitable place with the kit (§3.8); the rest of the world is whatever it rolled.

### 3.2 Water bodies
- **Ocean**: `e < climate.seaLevel`.
- **Lakes**: land where `valueNoise(seed, LAKE, gx, gy, climate.lakes.scale) > threshold` and `d < maxDrainage` and `r > minRainfall` and `e < mountainLevel`.
- **Rivers** (`catalog.rivers`): `count` rivers, each the existing north–south meander model with a random anchor column (`unit(seed, 0x21e5, i)`), half-width rolled from `halfWidth`, never within `keepAwayFromStart` of the start; a river cell that is ocean stays ocean. `riverModels(state)` returns them all; `waterModel(state).isWater(gx, gy)` = any river, lake, ocean, or the start pond.
- **Pond**: `pondModel` as today (`start.pond`).
- Kind of water (A1 autotile in `catalog.water.surface`): ocean → the ocean biome's water; lake → `pond`/`brackish`/`salt` by `sal` (< 0.33 / < 0.66 / else); river and pond → `fresh` (`icy` where t < 0.25; `swamp`/`marsh` inside swamp/marsh biomes; `blighted` in cursed regions).

### 3.3 Biome classification, `classify(f, lake)` with `f = fields(...)`
```
ocean       e < seaLevel:        t < 0.2 ocean_arctic; t < 0.65 ocean_temperate; else ocean_tropical
```

### 3.4 Region character
`savagery` and `alignment` tiers from `catalog.regions` (`below` thresholds). Cursed: ground swapped by `cursedGround`, plants in `cursedRemove` dropped, `cursedPlants` added; blessed: `blessedGround`, `blessedPlants`. `cellInfo(...).region = { savagery: "tame"|"wild"|"primeval", alignment: "cursed"|"neutral"|"blessed" }`.

### 3.5 Tiles
- Ground: layer 0 = `UF.Tiles.groundBase(kindId) + autotileShape(same kind)` where "same" compares the ground kind of neighboring cells (so biome borders get outlines). Water cells: layer 0 = `A1 base + autotileShape(neighbor is water of any kind)`; the ground kind under water isn't drawn.
- Peaks (`peak_rock`) get region 250 as well (UF_World no longer treats regions specially; UF_Tiles flags `peak_rock` impassable, region 250 is informational).
- Areas use tileset **91** (`UF.Tiles.TILESET_ID`), built at boot by UF_Tiles from `catalog.tilesets.surface`: A1/A5/B/C names as listed, A2 = `UF_GenGround_A2` (generated), flags copied from the `base` editor tileset except A2 kinds (`groundKinds[].passable === false` → 0x0f). Ground kinds are drawn in code (UF_Tiles), 22 kinds, sheet 768×576 (8 per row), 3× pixel art.

### 3.6 Objects placement
For every land cell that is not water (unless `onWater`), not in the start clearing, not a site cell (§3.7): the biome's `plants` table (plus region additions/removals) is walked in catalog order; for each `(objectId, chance)`: `patch = (1 − clump) + clump × smoothstep(0.5, 0.8, valueNoise(seed, salt(objectId), gx, gy, clumpScale))`, `roll = unit(seed, salt ^ 0x9e3779b9, gx, gy)`; place the first object whose `roll < chance × patch` (one object per cell). `avoidWater` = required distance (cells) from water (`waterDist` dilation up to 4). No caps: density is the point (expect 3 000–20 000 objects in a forest area). `UF.WorldGen.stats["ax,ay"]` keeps per-type counts of the last build.

### 3.7 Sites (from UF_History)
For each site returned by `UF.History.sitesIn(ax, ay)`: clear objects in the disc of radius `site.radius + 1`, then stamp `pieces` with `ctx.setObject(x + dx, y + dy, typeId)`. Sites never overlap water (History places them with `cellInfo`) and never within `sites.minDistanceFromStart` of the start.

### 3.8 The start
The start cell is the map centre (128,128); the climate there is blended toward `startClimate` (§3.1), so the player's home site (§2.7) always stands on habitable land. The **kit** (`start.kit.objects`): after normal placement, for each `(objectId, minimum)` count the objects of that id within `kit.radius[1]` of the start; if fewer than the minimum, add the difference at seeded random eligible cells in the ring `radius[0]..radius[1]` (not water, not occupied, not a site cell). `start.kit.wildlife` is UF_Wildlife's job (§5.7). **Map kit (user rule 2026-09-18, added at integration):** after placement and sites, count each object id in `start.mapKit.objects` over the whole map; for every class below its `min`, add seeded patches (`patchSize` objects each, clumped within 3 cells) on cells whose ground kind is in the class's `ground` list (else any walkable land), at least `keepAway` cells from the start and not on site cells, until the minimum is met. `start.mapKit.water.minFresh` fresh-water cells are guaranteed by the pond and rivers (a check reports if a seed falls short). Check `biomes.map_kit` verifies every minimum on the built map. **Revised 2026-09-18: there is no start pair any more.** The generator makes no start events (`start.pair` is unused); `start.clearRadius` is 0 (the site stamping clears its own disc). `map.note` gets `start.note`. The interim events-1-and-2 behaviour is removed once UF_Colonists lands (the generator keeps it only while `window.UF.Colonists` is absent, for the older suites).

## 4. Rendering conventions
- Tilemap children are sorted by `z`, then `y` (core `_compareChildOrder`). Ground layers z 0 and 4. **Objects and items: z = footY + priorityBonus** where `footY = Math.round($gameMap.adjustY(cellY) * 48 + 48)` (same as UF_Perspective25D uses for characters), `priorityBonus = under ? −100 : 0`, items −1. **Stance squares: z = footY − 50** and **designation markers: z = footY − 49** of their cell (revised 2026-09-18: above flat "under" objects such as grass tufts and stones at footY − 100, below the unit at footY, so the square is behind the person and never covered by grass). **Fog z = 1 000 000** (already).
- Sprites for objects/items are pooled and only exist for cells in view (`displayX/Y`, `screenTileX/Y`, plus a 3-cell margin, plus the sprite's own height above its cell). Rebuild the visible set when the display position changes by ≥ 1 cell, the zoom changes (`camera:zoomChanged`), the map changes, or `world:objectChanged` / `items:changed` fires. Never iterate 65 536 cells per frame.
- Anchor: bottom-center of the cell (`anchor = (0.5, 1)`, `x = (cellX + 0.5) * 48`, `y = (cellY + 1) * 48` in tilemap pixels) unless the image's sidecar (`img/characters/<name>.json`) gives `anchor: [ax, ay]` in exported pixels; then `anchor = (ax / frameWidth, ay / frameHeight)`. `UF.Sidecars.get(name)` (in UF_Objects) loads sidecars once via XHR and returns `null` until loaded.
- Character sheets are RMMZ `$` single-character sheets: 3 columns × 4 rows; frame size = bitmap.width / 3 × bitmap.height / 4 (or the sidecar's `frameWidth/Height`). Objects use one frame (sidecar `animations.stand[0]`, else column 1 row 0).
- Tint: `sprite.tint = parseInt(hex.slice(1), 16)`.
- Units keep being drawn by `Sprite_Character` (RMMZ). Wildlife/people are ordinary world units; their `data.tint` is applied by an alias in UF_Wildlife. A colonist's clothing tier changes `unit.image.characterName` (`start.pair[].tiers[tier]`) and the event's image (`UF.World.refreshUnitImage(id)`, §5.6).
