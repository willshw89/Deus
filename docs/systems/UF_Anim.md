# UF_Anim
The sprite-frame player (VISION V41, V58, V60, V61; user 2026-09-19: "The current animation thing... stop... all those animations are going to be depicted with sprites"). Every animation is a run of frames drawn in the art and named in the sheet's sidecar (`img/characters/<name>.json`, `animations`); worn and held equipment is a layer sheet stacked on the body's current frame. UF_Anim only chooses which frame each sprite shows. It moves, rotates, scales, tints and flashes nothing, and draws no placeholder tools. Where a sheet has no frames for a state, the unit or object shows its plain frames.

## The sheets it reads
- **Unit sheets** (AR-600 as in the generator prompts): 4 rows S, W, E, N; 20 columns: 0 stand, 1-3 walk, 4-6 work, 7 carry, 8-10 attack, 11-13 cast, 14 hurt, 15-17 death (the last frame is the remains), 18-19 idle. The sidecar names the columns: `animations: { stand, walk, work, carry, attack, cast, hurt, death (or dead), idle }`, each a list of column numbers; `frameWidth`/`frameHeight` (the frame size; without them RPG Maker's 3 × 4 geometry), `facings` (row order, default S, W, E, N), `frameMs` (default 150). Any other name in `animations` can be played with `UF.Anim.play(unit, name)`.
- **Object sheets:** `animations: { stand, sway, idle, lit, open, work }`, frames side by side in the top row of the character block (the same frame geometry UF_Objects uses).
- **Layer sheets:** `img/characters/$UF_Layer_<itemId>.png` with an optional sidecar (`frameWidth`, `frameHeight`, `facings`, `animations`, `behind`), drawn on the same frame grid as the body.

## How it works
**The clock.** One tick per `Game_Map.update` (a map update), so frames stop while the game is paused (UF_TimeSpeed skips map updates) and run faster at ×2–×8 like RPG Maker's own walk cycle. A sidecar's `frameMs` becomes `frameMs × 60 / 1000` ticks (150 ms = 9). Nothing reads `Graphics.frameCount`; nothing is random. Loops get a per-unit phase from the unit id and a per-object phase from `UF.World.hash32(0x5a1e, x, y)`, so a crowd or a forest doesn't move in unison.

**Units.** After each spriteset update, one pass over the map's character sprites picks every world unit's frame (the player and map events are left to RPG Maker). The state, first match wins:

| State | When | Frames |
|---|---|---|
| hurt | `UF.Combat.playHitAnimation` hit the unit | `hurt`, once |
| attack | `UF.Combat.playAttackAnimation`, or a work stroke: a hunter whose `hunt` job is working next to its prey, or a unit tagged `predator`/`monster` (or of such a wildlife species) next to its target (`data.targetId`, `data.intent.target`), every 30 map updates (or once per `UF.Beat` when it exists); the unit turns to face the target | `attack`, once |
| cast | `unit.data.casting` is truthy (no caster sets it yet) | `cast`, looping |
| carry | a `haul` or `fetch` job whose item (`params.itemId`) the unit holds | `carry`, stepped with RPG Maker's walk pattern (3 columns: column = pattern; otherwise `_pattern mod n`) |
| work | its job is in the `work` state (hunting included; the strokes above play `attack` over it) | `work`, looping |
| walk | moving, or stepping in place (UF_Jobs turns step animation on while working) | `walk`, with RPG Maker's walk pattern |
| idle | standing still with no job | `idle`, looping |
| stand | anything else | `stand` |

A state whose columns the sheet lacks shows the plain `walk` (moving or stepping) or `stand` frame. On a sheet with RPG Maker's own geometry (3 × 4, or a sidecar frame size equal to it), `walk` and `stand` are left to RPG Maker unchanged; on an AR-600 sheet they are cut from the sidecar's columns. A one-shot plays each column for `frameMs`, then the unit goes back to what it was doing; a new one-shot replaces a running one. Units more than 144 px outside the view keep their last frame (V50: only what is on screen animates; a unit is always framed once when its sprite is new). Frames are set with `Sprite.setFrame` (bushes split the frame the way RPG Maker does); RPG Maker's own `updateCharacterFrame` is skipped only for a unit whose frame UF_Anim chose.

**Death.** `UF.World.removeUnit` is wrapped. A removal is a death when the unit is being killed inside a wrapped kill call (`UF.Combat.onUnitDeath`, the `hunt` handler's `apply`), or `data.dead === true`, or `data.hp <= 0`. If the unit's sheet has death columns, the remains entry is recorded and a pooled sprite in the tilemap plays the columns in order (each for `frameMs`, in the unit's facing row, at the unit's depth z = foot row) from the frame the unit disappears; the last column then lies as the **remains** at z = foot row − 2 (above flat objects and stance squares, under items and units). If the sheet has no death columns, the unit is simply removed and nothing stays. Any other removal (a despawn, a test cleaning up) plays nothing. At most 24 death animations play at once (more lie still at once); deaths out of view record only the remains.

**Remains.** `UF.World.state.anim.remains` (saved with the world), one entry per death with death frames, at most 200 (the oldest dropped). An entry lies for catalog `anim.remainsHours` game hours (default 12; UF_Core's clock) and then disappears at once (no fade: V58/V60 forbid code-made motion). One sprite per cell (the newest remains there), only for cells in view plus 2; released sprites wait in a pool (48 kept). A loaded game redraws from the loaded list. Remains draw from ImageManager's cache when their sheet is loaded there, else from a bitmap loaded outside that cache, so a sheet that no longer exists leaves them invisible instead of stopping the game.

**UF_Combat's own motion is switched off, its logic untouched.** The committed UF_Combat.js (Gemini's d20 version, git HEAD on 2026-09-19; not edited here) animates in code; the working-tree rewrite for V64 (uncommitted, 2026-09-19 10:53) has none of that motion, keeps the three function names for UF_Anim and removes the unit itself on death, and with it the wraps below only add the sheet frames. The committed version: `playAttackAnimation` stores `event._combatOffset` and `event._combatAnim` (an 18 px lunge toward the target over 14 frames, flipping the walk pattern 0/2) and queues a code-drawn slash or claw mark in `UF.Combat.effects`; `playHitAnimation` stores an 8 px recoil and a red `setBlendColor` flash over 10 frames; `onUnitDeath` stores a 42-frame rotate, squash, crimson and fade collapse and removes the unit at its end. Its own `Sprite_Character.updatePosition`/`update` aliases apply these every frame. UF_Anim wraps the three functions at runtime:
- `playAttackAnimation` and `playHitAnimation`: the original runs (so everything it does besides motion still happens); right after it returns, the stored `_combatAnim` is replaced by an **inert timer** of the same length (14 or 10 map updates; its `update` only counts, so code that reads `event._combatAnim` as "in a combat reaction", such as UF_Fire's `units_hurt` check, still sees one), `_combatOffset` is set to `null`, a walk pattern its lunge changed is put back, and the strike marks the call added to `UF.Combat.effects` are removed (code-drawn animation). Then the sheet's `attack` or `hurt` frames play.
- `onUnitDeath`: the original runs (loot and equipment drop, the "SLAIN!" text); then its collapse is dropped (`_combatAnim`/`_combatOffset` = `null`) and the unit is removed at once as a death (the sheet's death frames, or nothing).
- A guard in `Sprite_Character.update` (before RPG Maker's update and UF_Combat's aliases) does the same to any other `_combatAnim`/`_combatOffset` it finds on a unit's event; a unit found in UF_Combat's collapse (`data._isDying`) is removed as a death at the next map update.
- The floating damage and status texts (`-3`, `CRIT -6!`, `MISS`, `SLAIN!`, `HOSTILE!`) are text, not animation, and are left alone (a decision for the user).

**Objects.** UF_Objects' `Sprite_Layer` is wrapped at runtime (`update`, `_assign`, `_release`; the file is not edited). Each layer keeps the list of its sprites that show an object whose sidecar names `sway`, `idle`, `lit`, `open` or `work` columns (the sidecars come from UF_Objects' own cache, `UF.Sidecars`). After the layer's update (and UF_Doors' door framing), each listed sprite shows, first match wins: `open` (a door type while `UF.Doors.isOpen` says so), `lit` (catalog `lit: true` or tag `lit`, or a job in the `work` state targets its cell), `work` (a job in the `work` state targets its cell, e.g. a craft at a workshop), `sway` (always), `idle` (always); otherwise its plain frame (the frame UF_Objects gave it, put back when a state ends; doors are re-framed by UF_Doors). A pooled sprite given another object or cell is reset in the `_assign` wrap, so a sprite reassigned to a rock shows the rock's frame and stops. Walls, tile objects and code-drawn objects have no frames to step. A sway or idle loop whose next column isn't due costs one comparison per frame.

**Equipment layers (V61).** For every unit in view: the slots `legs`, `torso`, `head`, `back`, `shield`, `weapon`, drawn in that order over the body; the older keys `clothes` (torso) and `tool` (weapon) are read when the slot is empty. A slot value is an item record id (UF_Items/UF_Jobs: shown only while the unit holds the item) or a catalog item type id (UF_Combat's test units). While the unit's job is in the `work` state, the weapon slot shows **the tool the job uses**: the equipped tool if its catalog `tool[jobType]` is above 0 (for `craft`, a recipe `tool` tag it has), else the best such tool in the unit's inventory. The layer sheet is `img/characters/$UF_Layer_<itemId>.png`; in NW.js the file's existence is checked first (a missing sheet is never requested, so no load error), and it loads outside ImageManager's cache. An item without a layer sheet draws nothing. Each layer is a pooled child sprite of the unit's `Sprite_Character`, on the body's frame: the same animation and frame index when the layer's sidecar names that animation, else the same column; the row from the layer's `facings`, else the body's row. **Behind the body:** a layer draws behind the body in the facings listed in its sidecar's `behind` (e.g. `["N"]`); without one, the `weapon` and `shield` layers are behind when the unit faces north (the item is on the far side of the body) and a `back` layer when it faces south. A layer behind is a child placed before a copy of the body frame (a child can't be drawn under its parent's own image), so the body covers it. Unequipping removes the layer at the next frame; its sprite goes back to the pool.

**Performance.** One pass for units and one for objects per frame, no allocation per frame in the passes, sheet geometry read once per bitmap, off-screen units skipped. `UF.Anim.perf` records the time spent (`performance.now`).

## API (`UF.Anim`)
| Member | Description |
|---|---|
| `play(unitOrId, name)` | Start a one-shot (`attack`, `hurt`, or any name the sheet's `animations` lists). Returns `true` when the sheet has those frames (the state is recorded either way) |
| `frameOf(unitOrId)` | What the unit's sprite showed at its last update: `{ want, shown, own, col, row, anim, k }` (`want` the state, `shown` the animation used, `own` false when RPG Maker drew the frame), or `null` |
| `layersOf(unitOrId)` | `{ list: [{ typeId, slot, behind, sprite }], over }` (`over`: the copy of the body drawn over layers behind it) |
| `layerSheet(itemId)`, `forgetLayers()` | The layer sheet entry `{ typeId, name, url, bitmap }` (loading starts on the first call) / forget the sheets looked up so far (a sheet added while the game runs; tests) |
| `objectAt(x, y)` | The object sprite on a cell and what it plays: `{ sprite, state, col, phase, tick }` or `null` |
| `animations(name)`, `deathColumns(name)` | A sheet's named column lists / its death columns, or `null` |
| `sidecar(name)`, `setSidecar(name, data)` | The image's sidecar (`undefined` while loading, `null` when none) / set one in code, which wins over the file (`null` drops it) |
| `isDeath(unit)` | Whether removing this unit now counts as a death |
| `remains()`, `remainsAt(x, y)`, `addRemains(entry)`, `clearRemains(filter?)` | The saved list / the entries on a cell / add one (cap applied) / remove matching entries (all without a filter), returns the number removed |
| `remainsHours()`, `nowMinutes()` | Catalog `anim.remainsHours` (default 12) / game minutes since the calendar's start (UF_Core's `$ufTime`; without it a saved counter) |
| `clock()` | Map updates counted (the animation clock) |
| `layer()`, `ghostAt(x, y)`, `spriteAt(x, y)`, `ghostCount()` | The death/remains layer of the map on screen (`activeCount()`, `poolSize()`, `kidPoolSize()`, `ghostCount()`, `sprites()`, `step()`) and shortcuts to it |
| `stroke()` | Run one work stroke now; returns the number of attacks started |
| `install()` | Wrap again anything another plugin replaced (runs at load, at boot and at every map start) |
| `installed` | `{ removeUnit, onUnitDeath, playAttackAnimation, playHitAnimation, define, hunt, objectLayer, objectAssign }` |
| `stats` | `{ deaths, deathsPlain, ghosts, created, layerSprites, oneShots, strokes, combatAttacks, combatHits, combatMotionStopped, strikeMarksDropped, guarded, culled }` |

| `errors` | The last 20 errors caught inside the plugin |
| constants | `FRAME_MS` 150, `TICK_MS`, `REMAINS_CAP` 200, `MAX_GHOSTS` 24, `POOL_KEEP` 48, `STROKE_TICKS` 30, `LAYER_PREFIX` `$UF_Layer_`, `SLOTS`, `BEHIND` |

## State it saves
`UF.World.state.anim = { remains: [{ x, y, image, index, frame, dir, until, tint? }], clock? }`: `frame` is the last death column, `dir` the facing, `until` the game minute it disappears, `tint` the unit's `data.tint` (a fixed species colour), `clock` only without UF_Core. About 90 bytes per entry, at most 200. Not saved: one-shots, death animations in progress (a save mid-death loads as still remains), pools, sidecars, layer sheets.

## Events
Emits `anim:death(unit, entry)` just before a dying unit is removed (`entry` `null` when its sheet has no death frames). Listens to `world:unitAdded` and `world:unitImageChanged` (sidecar requests).

## Wanted in other files (not edited here)
- **UF_Combat.js (Gemini):** the clean form of what UF_Anim now undoes at runtime: `playAttackAnimation` should not set `_combatOffset`/`_combatAnim` or change `_pattern`, and should not queue the code-drawn strike mark; `playHitAnimation` should not set the recoil offset or the red `setBlendColor` flash; `onUnitDeath` should remove the unit at once instead of the 42-frame rotate/squash/fade; the `Sprite_Character.updatePosition`/`update` aliases that apply `_combatOffset`/`_combatAnim` can go. The attack, hurt and death frames are then UF_Anim's alone. Also: `combat_popups` checks `popups.length >= 0` and can never fail; `rollDice`, the d20 roll and `spawnHostile` use `Math.random`; the popup layer creates a `Bitmap` per popup and per strike mark every frame.
- **Floating damage texts** (`-3`, `CRIT`, `MISS`, `SLAIN!`): text, not animation; kept. The user decides whether they stay.
- **UF_Fire.js:** its `units_hurt` check reads `event._combatAnim` as the hurt reaction; with UF_Anim it is an inert timer, so the check still passes, but the hurt reaction is now `UF.Anim.frameOf(unit).want === "hurt"`.
- **Catalog `anim.about`** still says remains fade over the last hour; they no longer fade (the catalog is not edited here).

## Known limits
- No sheet in the live catalog has any animation but stand/walk, so in today's game: no idle, work, carry, attack, cast or hurt frames show, deaths leave no remains (the morning's build left code-drawn remains), objects don't sway, and no equipment is drawn. Everything waits for the art (AR-600 bodies, layer sheets, object sidecars).
- The "behind" rule for layers without a sidecar `behind` (weapon and shield behind when facing north, back items behind when facing south) is Claude Code's reading of "behind the body when facing north for back items"; a layer sheet can state its own facings.
- A layer behind the body is covered by a second copy of the body frame: a semi-transparent body (a unit fading out, a bush's lower half) draws that copy over itself.
- Only the newest remains on a cell is drawn; older ones on the same cell wait in the save until it expires. Remains are recorded only for deaths in the area on screen.
- Off-screen units (more than 144 px out) keep their last frame; one-shots started off screen play on in the clock and may be over before the unit comes into view.
- The per-frame cost measured in play depends on the machine's load (2026-09-19, runs sharing the machine with other agents' tests): median 0.24 ms at 27 % CPU load, 0.23–0.30 ms at 45–51 %, 0.35 ms at 81 % (the mean 0.29–0.36 ms at 27–51 %, above the 0.3 ms budget in some runs); the same work back to back 0.10–0.14 ms.
- Not run in the RMMZ editor's Playtest (F5); not checked at ×8 speed.
