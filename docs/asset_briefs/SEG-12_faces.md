# Segment 12: faces (written 2026-09-18 by Claude Code)

The face sets of `docs/ASSET_REQUESTS.md` AR-700: one portrait sheet per species of `people` in `game/data/UF_WorldCatalog.json` (human, elf, dwarf, gnome, goblin, orc, automaton), both genders on one sheet, 8 cells per sheet in RPG Maker's face layout (4 columns × 2 rows of 144×144 = 576×288). A portrait is a shoulders-up bust on a plain dark ground, drawn at native resolution in the same micro-dithered manner as the map assets; it is where a person's size and bulk show, since every map sprite fits one 48×48 cell (VISION V44). The portraits are meant for the character sheet (VISION V49: portrait, grid inventory, equipment slots) and the colonist card. Today nothing in the engine draws a species portrait: the colonist card (`UF_ColonyOverseer.js`) draws text and gauges only, and the two windows that draw the stand-in face sheet (`UF_Dialogue.js`, `UF_Gumps.js`) are retired by AR-800; the character sheet (`UF_Sheet`, next build) will read `data.face = { sheet, index }` from a `faces` section of the catalog that Claude Code adds (`docs/design/WORLD_ARCHITECTURE.md` → Character sheet). The stock RPG Maker face sheets `Actor1..3` / `People1..4` named in AR-700's status are the placeholders until then. The named portraits in `game/img/faces/` are not approved (VISION → Proposed but not approved) and are not references. AR-700's row still says "96×96 exported" from the 3× standard; this segment follows the 2026-09-18 night rule (native resolution, one 144×144 cell per face, no scaling step).

## How to work this segment
1. Style: high-resolution 2.5D in the manner of the reference squares; every map asset sits inside one 48×48 screen-pixel square at native resolution (1 art pixel = 1 screen pixel at zoom 1), no 16×16 upscaling; `docs/ART_STANDARD.md` is binding. This segment is the one family that is not on the map: a portrait is a flat 144×144 cell (AR-700) drawn at the same native resolution with the same 1-px micro-dithered shading.
2. Projection: on the map, height leans up and to the left at 45° with the top, south and east faces visible (`docs/GUIDE_25D.md`); a portrait has no lean: a shoulders-up bust, head turned three-quarter toward the viewer's left, eyes toward the viewer, lit from the upper left, the same framing for every species so the seven sheets read as one set.
3. Palette: `art/palette/uf.hex` only (every index below is verified against the file); ≤ 32 colours per sheet; micro-dither (1-px checkers between ramp steps) is welcome; no gradients, no anti-aliasing, no blur, no baked shadow, no frame, no border, no text.
4. Masters: `art/masters/<id>.png` is the whole 576×288 sheet, every cell fully opaque on the same plain dark ground 86 `#000035`; magenta `#FF00FF` is the background of the raw generation step only (`art/raw/<id>/`, one bust per file, cut on magenta, then placed on the ground); alpha 0 or 255 everywhere after the clean step.
5. Sidecar: `art/masters/<id>.json` in the AR-600 form (frameWidth 144, frameHeight 144, anchor, facings, animations) plus `layer` "face", `species`, `stage` "adult" and the variant rows; each brief's Deliver line spells it out. Cell index = row × 4 + column, RPG Maker's face index.
6. Open the references named in each brief before drawing: the stand-in face sheet in `game/img/faces/` for the framing (a bust on a dark ground, shoulders up; its carved frames are not reproduced, the ground is plain) and the person reference square or stand-in walk sheet whose face the portrait must match. References and stand-ins only: nothing copied from them ships.
7. Contained: the crown of the hair (or casing) stays below row 8 of the cell and the shoulders inside columns 8–135; only the bottom edge (row 143) cuts the bust. Nothing touches the top, left or right edge of a cell.
8. Identity: row 0 = male variants (cells 0–3), row 1 = female variants (cells 4–7), four different people per row in one style (same ground, eye level, outline weight; no two alike at a glance); the automaton brief uses the two rows for two builds. Shoulders are bare: clothing tier 0 is unclad and clothing shows on the map sprite and in the equipment slots, not in the portrait.
9. Check: `"C:\Program Files\nodejs\node.exe" tools/art_check.js --sidecar --type face art/masters/<id>.png` (size 576×288, palette ≤ 32, alpha 0/255; ignore its 3×-grid check for 48-native masters until the tool is updated).
10. Export = copy into `game/img/faces/` unchanged (no scaling: masters are already at screen size) per `docs/ART_STANDARD.md` §5, after the user's line in `art/APPROVALS.md`; the catalog has no `faces` section yet (Claude Code adds `faces[species][gender]` with `UF_Sheet`), so write the delivered file name under "Notes for Claude Code" in `docs/ASSET_REQUESTS.md`.
11. Mark AR-700 in `docs/ASSET_REQUESTS.md` DELIVERED with the backticked file name, one species at a time (the other species stay open); the user approves each asset before it ships.
12. Order: human first (the playable species with the most colonists), then elf, dwarf, gnome (playable), then goblin, orc, automaton (`playable` false in `factions.species`: seen on strangers' sheets only). Verify a brief you edit with `"C:\Program Files\nodejs\node.exe" tools/check_briefs.js docs/asset_briefs/SEG-12_faces.md`.
