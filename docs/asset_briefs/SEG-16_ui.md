# Segment 16: ui (written 2026-09-18 by Claude Code)

The interface pieces the engine draws today in code or from stand-in files: the three stance squares and the target square under a unit's feet (`UF_Stance.js`, AR-034 and AR-031), the designation markers on ordered cells (`UF_Interact.js`, AR-035), the look tooltip beside the pointer (`UF_Look.js`, AR-032), the right-click menu (`UF_Interact.js`), the colonist card (`UF_ColonyOverseer.js`), the faction ledger (`UF_Factions.js`) and the chronicle (`UF_History.js`), the character sheet's frames (AR-701, next build), the shared window skin and touch buttons (AR-800, with AR-033), and the PAUSED and speed badges (`UF_DayNight.js`, `UF_TimeSpeed.js`). Two families: map markers, flat 48×48 squares drawn inside the tilemap under or around the sprites; and windows and parts, 9-slice skins and parts sheets in a carved-oak-and-parchment manner like the current skin stand-in, described here in our own words. Every window's text is drawn by the engine, so no piece carries text. Not in this segment (they need briefs of their own): the speech balloons, the 32×32 item icon set and the four container gumps that AR-800 also lists. The look cursor file of AR-030 is not drawn by any plugin today (the tooltip follows the pointer), so nothing here replaces it.

## How to work this segment
1. Style: the map markers are flat 48×48 squares at native resolution (1 art pixel = 1 screen pixel at zoom 1) in the same palette and micro-dithered manner as the reference squares; `docs/ART_STANDARD.md` is binding; no 16×16 upscaling.
2. Projection: a marker lies flat on its cell (no lean); windows and parts are flat UI. Where a piece shows a solid thing (a rail, a nail, a bezel) it is lit from the upper left, with a 1-px lit top-left edge and a 1-px dark bottom-right edge: the same light as the objects' lean in `docs/GUIDE_25D.md`.
3. Palette: `art/palette/uf.hex` only (every index below is verified against the file); at most 32 colours per asset; micro-dither (1-px checkers) is welcome, and on a marker a checker of colour and transparent stands for the translucency the code draws today; no gradients, no anti-aliasing, no blur, no baked shadow, no text.
4. Masters: `art/masters/<id>.png` on magenta `#FF00FF`, alpha 0 or 255. Sheets are rows of 48×48 frames or the fixed layouts each brief gives (RPG Maker's window-skin and button layouts, parts sheets with a table of rectangles). Translucency is never baked: where the engine wants it (stance squares at the catalog's alpha, windows at opacity 235–240, the tooltip at 82 %) it sets the sprite's opacity.
5. Sidecar: `art/masters/<id>.json` in the AR-600 form (frameWidth, frameHeight, anchor, facings, animations) plus the parts or skin table each Deliver line spells out.
6. Open the reference each brief names before drawing: the code-drawn piece it replaces (run the game, or read the plugin lines the Reference bullet cites) and the stand-in files in `game/img/system/`. Stand-ins and references only: nothing copied from them ships.
7. Contained: a map marker fills its 48×48 cell by design (the one family in these briefs that touches all four edges); every other piece keeps its outline inside its rectangle so the engine's cuts (9-slice borders, frame pieces) land on flat colour, and a piece the engine stretches is flat colour with no dither.
8. Check: `"C:\Program Files\nodejs\node.exe" tools/art_check.js --sidecar art/masters/<id>.png` (palette, alpha 0/255, frame grid as the sidecar says; ignore its 3×-grid check for 48-native masters until the tool is updated).
9. Export = copy into `game/img/system/` unchanged (no scaling: masters are already at screen size) per `docs/ART_STANDARD.md` §5, after the user's line in `art/APPROVALS.md`; each Deliver line names the export file. Two of them replace stock RPG Maker files (`Window.png`, `ButtonSet.png`).
10. Wiring: no piece of this segment is loaded by the engine yet (markers, tooltip, gauges, rows and badges are drawn in code; the windows use the stand-in skin). Write each delivered file name under "Notes for Claude Code" in `docs/ASSET_REQUESTS.md`; Claude Code switches the plugin to the file. Do not edit `game/js/`.
11. Mark the request row (AR-031, AR-032, AR-034, AR-035, AR-701, AR-800) in `docs/ASSET_REQUESTS.md` DELIVERED with the backticked file name; the user approves each asset before it ships.
12. Order: the three stance squares first (under every unit at a New Game), then the target square and the designation markers, then the window skin (every window changes at once), then the menu, tooltip, badges, card, ledger and chronicle parts, and the character sheet last (its window is the next build). Verify a brief you edit with `"C:\Program Files\nodejs\node.exe" tools/check_briefs.js docs/asset_briefs/SEG-16_ui.md`.
