### Why stopped ORG-0.2 JSONL alone does not yield a safe partial total

I parsed only event type, session ID, model label, assistant message ID and numeric usage fields from the retained JSONL; no message, tool output or private reasoning was exported. The four stopped logs for session 10894688-a905-44a0-9820-66a162c3729f contain 63 distinct assistant message IDs. Every ID repeats within its log, with identical usage snapshots; no ID overlaps another stopped log. Deduplication by message ID removes repeated stream events, but those snapshots are not demonstrably final per-call accounting.

Validation against the earlier **completed** session makes the limit concrete: across its 21:04 and 21:17 logs, 30 distinct assistant IDs have numeric usage snapshots whose deduplicated output-token fields sum to only **88**, while that same session's terminal result reports **132,632 output tokens**. The fields therefore cannot be summed as final output usage. A later terminal modelUsage snapshot now accounts for the second logical ORG-0.2 session through 05:41:45 CT. It does not make the individual stopped invocations' costs separately knowable or justify adding their partial JSONL fields to the cumulative terminal value.
