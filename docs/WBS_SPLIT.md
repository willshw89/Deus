**Parked performance relationship (D-2026-10-02-24):** a future worker lane may pass only plain-data snapshots through Comlink, leaving RMMZ responsible for drawing; it must preserve the sim/render boundary and use same-seed before/after overlay figures. The [versioned manifest](https://raw.githubusercontent.com/GoogleChromeLabs/comlink/v4.4.2/package.json) and [license](https://github.com/GoogleChromeLabs/comlink/blob/v4.4.2/LICENSE) identify Comlink as **Apache-2.0** at the verified version 4.4.2; this does not pin the future version, which must be tracked in the project licensing register before reuse. The Owner also plans visible/dirty Pixi `RenderTexture` chunks, sprite/item pooling, typed arrays, reduced per-frame allocation, staggered needs, roughly once-per-second off-screen work, per-system millisecond budgets, region-before-A* path checks and common-route caching. WASM is deferred until profiling shows hot water/path loops. These are future measured choices, not implementation instructions for SPLIT-0 through SPLIT-6; N and numeric budgets are TBD.

**World-size dependency (D-2026-10-02-25):** ORG-0.2 remains 1×1 and [WORLD-3x3](WBS_ORG.md) is planned first after its green result. Split work must preserve the 3×3 world's lazy/eager equivalence and no-late-faction-start rules from DEC-065/070, including the conditional eager fallback. The soft worldgen data contract and RMMZ decoupling do not replace the hard 3×3 worldgen exit gates or advance DEC-037.

Why the player cares: stable world data should load and save predictably while rendering can change without a second simulation; tunable densities and traceable weights should use explicit data. The Owner's first post-worldgen gameplay priority remains WBS-SIM SIM-8 (arrive, gather, hut, night, fun assessment). These soft architecture tasks do not authorize postponing that loop behind a full engine rewrite. The precise bounded first implementation brief is still to be approved.
