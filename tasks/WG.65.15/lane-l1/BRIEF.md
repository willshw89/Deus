## Goal
The SIM.50.01 audit (`docs/audits/LIVING_WORLD_GAP_AUDIT.md`, finding **F-04**, section 2.6, section 6 step 2) found no mass ledger anywhere: destroyed strata become air, mining 4 strata yields 2 stone, digging and quarrying create stone, fire deletes items, and nothing catches it. Build the ledger every later system will prove LIFE-001 against: a host-agnostic, integer, per-material-class conserved-total ledger with named sources and sinks, a transform table that encodes the Owner's matter rules, an assert/audit API, and a deterministic long-run harness that fails if matter appears or disappears.

## Owner rules the ledger must encode (non-negotiable)
1. **Matter is conserved** (LIFE-001, `docs/RISK_REGISTER.md:60`; ADR-003 A7.8 Q-MASS). After world registration is sealed, the total of every conserved class changes only through (a) transforms that move mass between classes/forms with the total unchanged, or (b) a **named** source or sink from the declared list, each call logged with a cause.
2. **Decay chain:** objects/structures -> ruin -> rubble -> soil/sediment -> rock (lithification). These are allowed transforms in the data table; skipping or reversing a stage is only allowed where the table says so.
3. **Metals rust to mineral traces, never to new ore** (LIFE-002, `docs/RISK_REGISTER.md:61`; Owner ruling D-5 "ore never respawns"; V74, V83, INV-SIM-03). Per-element conservation for the finite metals Fe, Cu, Ag, Au, Pt (the original WG.65.15 row, `docs/worldgen/DEUS_WORLDGEN_WBS.md:254`): an iron item that rusts becomes iron-bearing trace mineral and the Fe total is unchanged. Electrum is an Au+Ag alloy whose mass is conserved against the gold and silver ledgers (`game/data/DEUS_ResourceRegistry.json:471`).
4. **No ore respawn:** no transform, source or config entry may output an ore class. Ore totals can only move between forms (in place -> mined ore item) or decrease (smelted to metal, lost to a named sink). The ledger must reject any transform table or source list whose output is an ore class, at config load time as well as at call time (ADR-003 A7.8 "A test fails any transform table entry whose output is an ore material").
5. **Spell-conjured matter** (DEC-018 open sub-question, `docs/OWNER_DECISIONS.md`, "Conjured matter ... PM default"): the PM default is a named `magic` source and a named `magic` sink, logged like rain/evaporation. **The Owner has not confirmed this.** So the source/sink list is **data-driven** (a config table, not code branches): if the Owner rules otherwise, only the table changes. Write this as an Owner question in your REPORT; never decide it.

## What to build
1. **`game/js/sim/ledger.js`** (plus optional `ledger_*.js`/`ledger_*.json` data files in the same folder): a pure module.
   - **Host-agnostic, ADR-003 A2.3-A2.5 compliant** (`docs/adr/ADR-003_sim_render_split_and_lod.md` Rev 3; the ADR is PROPOSED, cite it as such): CommonJS subset only (`module.exports = ...`; `require("./relative")` only, and only for other `game/js/sim/ledger*` files). It must not name any identifier on the ADR A2.3 forbidden list: `window`, `document`, `globalThis`, `self`, `global`, `process`, `require` of anything non-relative, `nw`, `localStorage`, `setTimeout`, `setInterval`, `requestAnimationFrame`, `performance`, `Date`, `PIXI`, any RMMZ manager or `Game_*`/`Scene_*`/`Sprite*`/`Window_*`/`$game*`/`$data*`, `UF`, `DEUS`, `Math.random`. No RMMZ dependency of any kind.
   - Note: ADR-003 A2.4 sketches the eventual home as `game/js/sim/kernel/ledger.js`. SIM.00.02 owns the kernel layout and may move the file; keep the module self-contained so that move is a rename. Say this in your REPORT.
   - **Integer units only.** Every amount is a non-negative safe integer in named mass units (ADR-003 A7.8: "mass units (integer; one table per material and form, set by SIM.40.01 with WG.65.15)"). Reject floats, NaN, negatives, non-numbers and results beyond `Number.MAX_SAFE_INTEGER` with a thrown error that names the class and cause.
   - **Per-material-class totals.** Default class table as data, derived from and citing `game/data/DEUS_ResourceRegistry.json` (its `conservedClasses` and invariant formula around lines 500-509) and the audit's list (strata by material, loose items by material, fluid volume, biomass, carbon/ash): at minimum stone/rock, rubble, soil, sediment, ash/charcoal, wood/organics, biomass, water (fluid, with an ice form), mineral trace/rust, gems, and each finite metal element Fe, Cu, Ag, Au, Pt in its ore and metal forms. Keep **forms** (strata, loose item, placed object/structure, ruin stage, fluid, held-in-creature) as a second axis as in ADR-003 A7.8 (Q-MASS[family] summed over forms), or justify a simpler equivalent in the API doc.
   - **API (names are a suggestion; document whatever you choose in `tasks/WG.65.15/lane-l1/LEDGER_API.md`):** `createLedger(config)`; `register(cls, form, amount)` during world setup; `seal()` after which only the calls below may change totals; `transform(fromCls, fromForm, toCls, toForm, amount, cause)` (must be an allowed table entry; total unchanged; element-conserving for metals); `source(name, cls, form, amount, cause)` and `sink(name, cls, form, amount, cause)` where `name` must be in the declared list (defaults: `magic`, `world-edge`, `debug-explicit`; rain/evaporation may be declared for water per ADR-003 A7.9); `totals()` / `total(cls)`; `audit(recount)` that compares the ledger's expected totals with an independent recount supplied by the caller and returns a structured diff; `assertBalanced(recount)` that throws on any diff; per-interval identity `delta(total) = sum(sources) - sum(sinks)`; a bounded or summarised event log (no unbounded growth in long runs); `snapshot()`/`restore()` (JSON-safe) and a deterministic `checksum()`.
   - Deterministic: no clocks, no randomness inside the module; iteration order fixed (sorted keys), so identical call sequences give identical checksums.
2. **`tools/sim/test_ledger.js`** (unit tests) printing one `PASS <name>`/`FAIL <name>` line per check and a final `RESULT: <n> passed, <m> failed`, exit 0 only if all pass. Cover: every API path and error path above; ore-output rejection at config load and at call time; rust keeps the element (Fe item -> Fe trace, Fe total unchanged, ore total unchanged); decay chain ruin -> rubble -> soil/sediment -> rock conserves the total; undeclared source name rejected; `magic` source/sink logged with cause; seal enforcement; snapshot/restore round trip and checksum stability; a **purity check** of every `game/js/sim/ledger*` file (static token scan for the ADR A2.3 identifiers ignoring comments and strings, plus loading the module in a `vm` context that exposes only ECMAScript built-ins with `Math.random` replaced by a throwing function).
3. **Mutation checks**, in the same file or `tools/sim/test_ledger_mutants.js`: apply each source mutant to an in-memory copy of the module text (never edit the real file on disk) and show the suite kills it, printing `PASS mutant_<name>_killed`. At least: transform that drops 1 unit; transform that adds 1 unit; source that skips the name check; ore output allowed; rust that changes element; seal not enforced; float accepted; audit that ignores a class; checksum that ignores order or a class. Also a mutant of the purity check itself (a module that names `window` or calls `Math.random` must fail it).
4. **`tools/sim/test_ledger_longrun.js`**: a deterministic long-run harness. A toy world **inside the test/fixture code, not in `game/js/sim/`**: sparse 32x32-cell chunks allocated on demand across 32 layers `-16..+15` (DEC-013 as amended; ADR-003 Rev 3 A15), 5-ft cells, 10-ft layers, 2-ft slices, holding per-cell material amounts. A seeded integer PRNG (mulberry32/hash32 style, written in the test; no `Math.random`). At least 100,000 randomized operations on at least 3 seeds: decay steps along the chain, rust, mining (in place -> loose), building (loose -> structure), fire (organics -> ash/charcoal), water movement, a few `magic` sources/sinks and `world-edge` sinks. After every K operations (and at the end) recount the toy world independently and `assertBalanced` against the ledger; also check the finite-metal element totals and that ore never increases. It must **fail** (non-zero exit, named failure) when matter appears or disappears: demonstrate with injected faults (a world op that mutates cells without telling the ledger; one that creates ore; one that deletes 1 unit) that each makes the harness fail, printed as `PASS fault_<name>_detected`. Print the per-class totals at start and end, operation counts per kind, the seeds, run time, and `RESULT:`. Keep runtime under about 2 minutes on this laptop.
5. **Docs and report** under `tasks/WG.65.15/lane-l1/`: `LEDGER_API.md` (API, class/form table, transform table, source/sink table, how later packages hook it on `levels:strataChanged` at `game/js/plugins/DEUS_Levels.js` around line 1558 and on the item and fluid writers, without doing it; which existing leaks from audit F-04 each hook would catch), and `REPORT.md` (below).
