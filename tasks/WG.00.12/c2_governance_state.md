## Interpretations for Review (Grok, please attack these)
- The non-terminal allowlist accepts aliases: TODO ← PLANNED, QUEUED, OPEN, NEW, BACKLOG, NOT_STARTED, PENDING, PROPOSED, DRAFT, REOPENED; IN_PROGRESS ← ACTIVE, WIP, STARTED, ASSIGNED, ONGOING, IN_WORK; REVIEW ← IN_REVIEW, UNDER_REVIEW, AWAITING_REVIEW, PENDING_REVIEW, READY_FOR_REVIEW, FIX_READY, VERIFY_PENDING, VERIFY_REQUEST, CHANGES_REQUESTED; BLOCKED ← ON_HOLD, SUSPENDED, PAUSED, WAITING, DEFERRED.
- The first phrase of a status cell must be exactly a known status: `QUEUED behind 19A` is a closure; `QUEUED (behind 19A)` is not. `PASSED` and `MERGED` are not closure words, so `REVIEW (tests passed)` stays non-terminal.
- `A ← B` means A (B was the old state); `A ↔ B` makes both A and B candidates.
- Grandfathering covers 4.4 only. The epoch is `a12f94a7`; the coordinator moves `GOVERNANCE_EPOCH` forward to the hook-install commit.
- A cited review artifact must mention the record's ID, be last committed by the closer and record no failing verdict for it. A verdict line scoped with "for / on / of <IDs>:" applies only to the IDs it names; a scope that names no item ID (`Verdict on 2026-09-25: FAIL`) applies to everything. A review that records no verdict at all still backs a closure. The artifact need not live in the closer's whitelist (the range gate's 4.4 check on the artifact's own commit covers that).
- A `DEC-xxx` backs an owner closure only if the entry's heading or body (up to the next heading) names the record's ID.
- A cell in a `Writer → Reviewer` column without an arrow (`Grok (review only)`) names a writer and no reviewer.
- A reachable commit hash remains sufficient 4.1 evidence, as in Lane C2; the review artifact carries the independent check.
- Prose claims are judged per sentence: every ID in a sentence with a non-negated closure word is claimed.

## Known Limits
- Identity is declared, not authenticated: a commit subject `[grok]` is trusted as Grok's. `--range` catches such a commit only through 4.4 on the paths it touches.
- A negator within three words before a closure word cancels it (`not pending, DONE` is caught; `not pending DONE` is not). Prose skips hyphenated closure words (`DONE-ish`).
- Homoglyphs outside NFKC (Cyrillic `О` in `DОNE`) are not folded; they make the value unknown, which counts as a closure.
- A test log is not tied to the script cited beside it: any committed passing log plus any existing script is a test run. Requiring the log to name its script would reject the real logs in `tasks/WG.00.08/evidence/`, which do not.
- Sub-item rows (`WG.00.12/C1`, `A10-1/x`) are not read as leaves or defects, so their status is not checked.
- Failing verdicts are found by pattern (`Verdict` lines, headings and Verdict / Result / Outcome columns). A review that rejects in other words ("this does not pass") still backs a closure.
- `git commit --amend`, `--no-verify` and hooks living in the shared common `.git/hooks` are as described for Lane C2; DEC-004 is still `OPEN`, and the hook is **not installed**.
- The range gate trusts `Merge branch '...'` subjects for lane hints; a hint can only narrow a commit to one lane, never widen it (an agent that does not hold the hinted lane is rejected; see F13).
