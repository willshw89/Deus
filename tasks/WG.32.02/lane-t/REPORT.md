## What the templates contain and how they are laid out

- **Pixels.** Background is alpha 0 by default, or `#FF00FF` with `--bg magenta`. Grid lines are 1 px wherever x or y is a multiple of the sheet's `gridPx`, plus the last column and row. Every catalogue slot rect gets a 1-px outline. Stratum ticks are 4 px long, drawn inward from both side outlines. Labels use a 3x5 bitmap font defined in code as strings, with no anti-aliasing. Grid, outline and tick colour is `#00FFFF`; label colour is `#FFFF00`. The master palette contains neither colour, and the generator refuses any catalogue palette that does.
- **Labels.** Each label reads `<4-digit slot index> <scaleRow short code>`. The short code is the first letter of each scaleRow word, with number words kept whole, e.g. `GEOM_STRATUM_3` → `GS3`. If that does not fit, the label is the index alone; if the index does not fit either, there is no label. Each slot's sidecar entry records the full scaleRow and which of the three label forms was used.
- **Geometry.** The generator reads geometry only from the file the catalogue references (or `--geometry`), and all geometry values are read in one function, `geometryParams`. `GEOM_STRATUM_<d>` slots need frame height `stratumPx[0..d-1]` summed; `GEOM_LAYER_FACE` slots need `layerPx`. Ticks mark the top row of each stratum, counted up from each frame row's bottom. Slot heights that disagree with the geometry are refused (`STRATUM_HEIGHT_MISMATCH`), and so is a catalogue whose recorded geometry sha256 differs from the file (`GEOMETRY_SHA_MISMATCH`). These conventions are my reading of the BRIEF; see escalation E2 and E3.
- **Sidecar.** It has the BRIEF's fields (`sheetId, w, h, gridPx, bg, gridColour, labelColour, geometrySha256, stratumPx`, and per slot `slotId, entryId, scaleRow, frameClass, footprint, anchor, x, y, w, h`). It adds `format, generator, kind, group, runtimeFile, bgRgba, catalogueSha256, tilePx, layerPx, png, pngSha256`, and per slot `frames, envelope, paperDoll, strataTicks, label`.
- **Output folder.** `INDEX.md` and `README.md` are kept. Template pairs the generator wrote earlier are replaced, or deleted when their sheet has left the catalogue. Any other file is refused (`OUT_DIR_UNEXPECTED_FILE`), and so is a template PNG changed since it was written (`OUT_DIR_MODIFIED_TEMPLATE`). A painted file is therefore never overwritten.
- **Line endings.** JSON sha256 values are computed on text with CRLF folded to LF. A CRLF checkout (system `core.autocrlf=true` on this machine) therefore hashes the same as the LF original, and produces byte-identical templates.

## Not done / known problems

- The final run against `art/catalogue/catalogue.json` has not happened; the BRIEF defers it until Lane S merges. Everything was tested against my fixture only, and the real catalogue may disagree with the conventions in escalation E2–E4.
- The BRIEF contradicts itself on the fixture ATLAS size (escalation E1). I did not stop the lane over it: the fixture is 4096x4096, and the generator draws a partial last grid cell.
- Stratum-derived slots are recognised only by the scaleRow ids `GEOM_STRATUM_<d>` and `GEOM_LAYER_FACE` (E3). If Lane S uses other ids, those slots silently get no ticks and no height check.
- The generator does not recompute the contract's `48*ceil(max/48)` slot rule. It checks exact frame-class sizes, that the envelope fits in one frame, and stratum heights (E4).
- `build_fixture.js` is my stand-in for Lane S's builder, and it encodes my reading of the contract. The tests use it to rebuild the fixture after a geometry change.
- A horizontal grid line can cross a label when a slot's top is not on the grid; the label pixels are drawn over it. The fixture layout avoids this. The label test decodes only label-colour pixels.
- `templates.repo_untouched` compares `git status` before and after the run, so a change made by someone else in the checkout during a run would make it fail.
- No `docs/systems/` page. `docs/` is outside this lane's allowedPaths, so the documentation is the headers of the two tools, `art/templates/README.md` and the generated `INDEX.md`.
